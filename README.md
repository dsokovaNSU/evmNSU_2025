## 1. Введение

В современном мире студентам легко потеряться в огромном потоке информации. Постоянный стресс, высокая нагрузка и трудности с оценкой собственного прогресса — справляться с этим самостоятельно становится всё сложнее. Именно поэтому растет потребность в эффективных инструментах для организации учебного процесса.

Одним из таких инструментов станет десктопное приложение, которое поможет студентам формировать учебный план, ставить цели и отслеживать свои достижения. С его помощью пользователи смогут управлять расписанием и выстраивать комфортный темп работы над важными и срочными задачами. Снизить уровень стресса поможет интерактивный милый маскот.

Главная идея проекта — вдохновить пользователей на осознанную организацию своего времени и помочь им навести порядок в учебе, мыслях и чувствах.

## 2. Предметная область проекта

Современный учебный процесс требует от студентов высокого уровня самоорганизации, гибкости и умения справляться с тяжелыми нагрузками. В условиях плотного расписания, обилия дедлайнов и необходимости совмещать учебу с личной жизнью, стандартных подходов к планированию становится недостаточно. Студенты остро нуждаются в комплексных цифровых инструментах, которые не просто фиксируют задачи, но и помогают сохранять высокую продуктивность без перегрузок.

### 2.1 Существующие проблемы

**1. Отсутствие единого инструмента.** Информация о парах и заданиях рассредоточена по мессенджерам, вузовским приложениям и блокнотам, а цели приходится вести в отдельных сервисах. Из-за этого студент теряет фокус, путается в приложениях и пропускает важные сроки.

**2. Несоответствие специфике учебы.** Большинство таск-менеджеров на рынке созданы для рабочих процессов и бизнеса. Они не учитывают особенности студенческой рутины: пары, сессии и типы учебных заданий. Студент вынужден тратить время на адаптацию приложения под себя.

**3. Монотонный интерфейс.** Существующие планировщики часто имеют скучный дизайн. Такой интерфейс быстро надоедает и никак не мотивирует ежедневно возвращаться к планированию.

### 2.2 Предполагаемое решение

Для решения этих проблем предлагается создать десктопное приложение «StudyHard», которое объединит в себе все необходимые инструменты планирования.

В приложении будут учтены особенности учебной рутины: пользователь сможет гибко настраивать напоминания и дедлайны с учетом расписания пар, сессий и долгосрочных задач (например, для получения автомата). За мотивацию и снижение тревожности будет отвечать интерактивный маскот-помощник — он будет живо реагировать на успехи студента, подбадривать его и помогать справляться со стрессом.

## 3. Требования к программному решению

### 3.1 Роли

**1. Пользователь**

Пользователь — студент, использующий десктопное приложение «StudyHard» для планирования учебы, ведения задач, работы в режиме фокусировки и взаимодействия с маскотом. Единственная роль в системе.

### 3.2 Функциональные требования для роли Пользователь

#### 3.2.1 Управление расписанием на день

Для добавления, удаления и изменения пары на выбранный день пользователь использует кнопки «+», «Удалить» (в виде мусорной корзины) и «Изменить пару» (в виде гаечного ключа).

Предусловие: пользователь находится на экране расписания и выбран конкретный день. Для изменения или удаления пара должна существовать в расписании.

Сценарий 1: добавление пары. Пользователь нажимает «+ Пара». Предлагается ввести название пары или пропустить данное действие, тогда название заполняется плейсхолдером «Name». Пара добавляется в расписание выбранного дня.

Сценарий 2: изменение пары. Пользователь нажимает «Изменить пару». Текущее название заменяется на новое, введённое пользователем.

Сценарий 3: удаление пары. Пользователь нажимает «Удалить». Запрашивается подтверждение удаления. При подтверждении пара удаляется из расписания.

Сценарий 4: отказ от удаления. Пользователь не подтверждает удаление — пара остаётся без изменений.

#### 3.2.2 Сохранение шаблона недели

Пользователь может сохранить статичное недельное расписание для чётной или нечётной недели с помощью кнопки «Сохранить неделю».

Предусловие: пользователь находится на экране расписания, и в текущем расписании есть хотя бы одна добавленная пара.

Сценарий 1: успешное сохранение. Пользователь нажимает «Сохранить неделю». Запрашивается подтверждение сохранения. При подтверждении шаблон недели сохраняется.

Сценарий 2: отказ от сохранения. Пользователь не подтверждает действие — сохранение не выполняется.

#### 3.2.3 Создание целей

Для фиксации крупной цели с дедлайном используется кнопка «Новая цель». Внутри созданной цели пользователь может добавлять шаги с помощью кнопки «+ Подзадача». Создание цели включает установку дедлайна и добавление подзадач.

Предусловие: Для добавления подзадачи родительская цель должна быть уже создана.

Сценарий 1: невалидный дедлайн. Выбор невалидной даты в качестве дедлайна невозможен — выводится сообщение об ошибке, и пользователь возвращается в состояние до нажатия кнопки; цель не создаётся.

Сценарий 2: валидный дедлайн. Пользователь выбирает валидную дату в качестве дедлайна — цель создаётся и отображается в списке целей.

Сценарий 3: добавление подзадачи. Внутри созданной цели пользователь нажимает «+ Подзадача» и вводит её название — подзадача добавляется к цели.

#### 3.2.4 Удаление целей и подзадач

Пользователь может удалять созданные цели и их подзадачи.

Предусловие: удаляемая  цель или подзадача существуют.

Сценарий 1: удаление цели. Пользователь выбирает цель и нажимает «Удалить». Запрашивается подтверждение удаления. При подтверждении цель удаляется вместе со всеми подзадачами.

Сценарий 2: удаление подзадачи. Пользователь выбирает подзадачу и нажимает «Удалить». Запрашивается подтверждение. При подтверждении подзадача удаляется, цель остаётся.

Сценарий 3: отказ от удаления. Пользователь не подтверждает действие — цель или подзадача остаётся без изменений.

#### 3.2.5 Отметка о выполнении

Пользователь может изменять статус целей и подзадач, отмечая их выполнение с помощью чекбокса (галочки).

Предусловие: цель или подзадача существуют.

Сценарий 1: отметка о выполнении. Пользователь устанавливает галочку — статус цели или подзадачи меняется на «выполнено», начисляются баллы.

#### 3.2.6 Управление напоминаниями к паре

Для добавления, удаления и изменения напоминания к выбранной паре пользователь использует кнопки «+», «Удалить» (в виде мусорной корзины) и «Изменить напоминание» (в виде гаечного ключа).

Предусловие: пользователь находится на экране расписания, и выбрана конкретная пара. Для изменения или удаления напоминание должно существовать.

Сценарий 1: добавление напоминания. Пользователь нажимает «+». Предлагается ввести текст напоминания или пропустить данное действие, тогда напоминание создается пустым. Напоминание закрепляется за выбранной парой.

Сценарий 2: изменение напоминания. Пользователь нажимает «Изменить напоминание». Текущий текст заменяется новым.

Сценарий 3: удаление напоминания. Пользователь нажимает «Удалить». Запрашивается подтверждение удаления. При подтверждении напоминание удаляется.

#### 3.2.7 Просмотр напоминаний к паре

Пользователь может просмотреть все напоминания, привязанные к конкретной паре.

Предусловие: пользователь находится на экране расписания, и выбрана конкретная пара.

Сценарий 1: просмотр. Пользователь нажимает на значок управления напоминаниями к паре — отображается список привязанных к ней напоминаний.

#### 3.2.8 Персонализация интерфейса и маскота

Для настройки рабочего пространства пользователь нажимает кнопку «Кастомизация» (иконка шестерёнки) для входа в режим редактирования. В этом режиме доступны: изменение цветовой схемы всего приложения с помощью кнопки «Стиль окна» и изменение внешнего вида маскота. Уникальные визуальные стили приобретаются в «Магазине» за заработанные баллы.

Предусловие: пользователь находится в режиме кастомизации. Для применения уникального стиля он должен быть приобретен ранее

Сценарий 1: изменение цветовой схемы. Пользователь нажимает «Стиль окна» и выбирает доступный стиль — выбранный стиль применяется ко всему интерфейсу.

Сценарий 2: изменение внешнего вида маскота. Пользователь выбирает доступный элемент маскота — элемент отображается в рабочем пространстве.

Сценарий 3: применение платного стиля без покупки. Пользователь пытается применить недоступный стиль — выводится сообщение о необходимости приобрести стиль в «Магазине».

#### 3.2.9 Покупка улучшений за баллы

Для перехода к товарам пользователь нажимает кнопку «Магазин» (иконка в виде павильона). В открывшемся меню он может потратить заработанные баллы на новые элементы для кастомизации маскота и стилей окон рабочего пространства, нажимая кнопку «Купить» под выбранным предметом.

Предусловие: пользователь находится в меню «Магазин». Предмет должен существовать в каталоге и ещё не быть купленным пользователем.

Сценарий 1: недостаточно средств. Если стоимость предмета превышает сумму на балансе пользователя, кнопка «Купить» остаётся неактивной.

Сценарий 2: достаточно средств. Если баланса пользователя хватает для покупки выбранного предмета, кнопка «Купить» активна — при нажатии стоимость списывается с баланса, предмет добавляется в коллекцию пользователя.

### 3.3 Нефункциональные требования

#### 3.3.1 Производительность

- Время запуска приложения — не более 3 секунд на типовой конфигурации.

- Отклик интерфейса на действия пользователя — не более 200 мс.

- Операции с задачами (создание, редактирование, удаление) — не более 500 мс.

#### 3.3.2 Нагрузка

- Приложение рассчитано на одного пользователя (локальное использование).

- Корректная работа при хранении до 1000 задач и событий расписания без заметной деградации.

#### 3.3.3 Надёжность

- Корректное завершение работы без потери данных.

- Периодическое автосохранение данных (не реже одного раза в 30 минут).

#### 3.3.4 Безопасность

- Валидация пользовательского ввода во всех формах.

- Корректная обработка исключений без раскрытия внутренних деталей системы пользователю.

#### 3.3.5 Масштабируемость и расширяемость

- Архитектура приложения — модульная.

- Настройки приложения (тема, интервалы напоминаний, длительность сессии фокуса) хранятся отдельно и изменяются без пересборки.

#### 3.3.7 Удобство использования

- Интерфейс на русском языке.

- Поддержка полноэкранного режима

#### 3.3.8 Переносимость

- Поддержка основных настольных ОС: Windows, macOS, Linux.

#### 3.3.9 Документация

- Код снабжён комментариями к ключевым модулям и функциям.

#### 3.3.10 Поддержка принципов ООП

- Код построен на принципах объектно-ориентированного программирования: инкапсуляция, наследование, полиморфизм, абстракция.
